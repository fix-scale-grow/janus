# Permits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A toggleable Permits feature: universal permit tracking per deal, agent-researched jurisdiction playbooks the client verifies fact-by-fact, a document checklist with a reusable workspace locker, and an AI-fill/guided-fill worksheet with a per-field approval sweep gating a branded PDF.

**Architecture:** New `permits` tRPC module + five Prisma models (Jurisdiction, PermitPlaybook, Permit, PermitDocument, PermitInspection) plus LockerDocument and AppSetting columns. All Json columns parse at the boundary in `@crm/db/permits`. Intelligence stays in `apps/agent`: playbook research is a dispatched task writing unverified drafts (the `record_fact` write class); AI fill is a conversational approval-carded tool. The stage trigger is deterministic in the API (a prompt banner, not an agent run) because dispatched sessions are denied gated writes — this is a deliberate adaptation of the spec's "confirm card", preserving its behavior on existing rails; the per-rule autonomy dial is deferred.

**Tech Stack:** Next 16 app router, NestJS + nestjs-trpc, Prisma, zod, @react-pdf, eve agent tools, bun test, Playwright walkthrough.

**Spec:** docs/superpowers/specs/2026-09-13-permits-design.md
